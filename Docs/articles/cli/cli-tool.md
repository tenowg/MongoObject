# MongoObject CLI Tool

The MongoObject CLI Tool (`mo`) is a command-line utility that automates the generation and execution of MongoDB schema migrations for your MongoObject projects. It analyzes your document definitions and generates migration files that handle schema changes, index creation, and other database operations.

---

## Installation

The CLI tool is distributed as a NuGet global tool. Install it using the .NET CLI:

```bash
dotnet tool install --global Tenowg.MongoObjects.CliTool
```

After installation, you can use the `mo` command from any terminal:

```bash
mo --help
```

### Updating the Tool

To update to the latest version:

```bash
dotnet tool update --global Tenowg.MongoObjects.CliTool
```

### Uninstalling the Tool

If you need to remove the tool:

```bash
dotnet tool uninstall --global Tenowg.MongoObjects.CliTool
```

---

## Prerequisites

Before using the CLI tool, ensure:

- **.NET 10 SDK** is installed
- **MongoDB 4.0+** is running and accessible
- Your project has **MongoObject configured** with a valid connection string
- Your project contains **MongoObject document definitions** with the `[MongoObject]` attribute

---

## Quick Start

The CLI tool uses a two-step workflow:

### Step 1: Build Migrations

Generate migration files based on your current document definitions:

```bash
mo migrate build
```

This command:
- Analyzes your MongoObject document definitions
- Connects to your MongoDB instance
- Detects schema differences between your code and the database
- Generates a `MigrationBuilder.cs` file with all necessary operations

### Step 2: Run Migrations

Execute the generated migration:

```bash
mo migrate run
```

This command:
- Loads the generated migration file
- Executes all database operations
- Creates collections, indexes, and applies schema changes

## Command Reference

### Global Options

All commands support these options:

| Option | Short | Description | Default |
|--------|-------|-------------|---------|
| `--project` | `-p` | Path to the project directory | `.` (current directory) |
| `--environment` | `-e` | Target environment configuration | `Debug` |
| `--verbose` | `-v` | Display detailed logs for debugging | `false` |

### migrate build

Generates migration files from your document definitions.

```bash
mo migrate build [OPTIONS]
```

**Options:**

| Option | Short | Description |
|--------|-------|-------------|
| `--framework` | `-f` | Target framework (required if project multi-targets) |
| `--ci-deploy` | `-c` | Non-interactive mode for CI/CD validation |

**Examples:**

```bash
mo migrate build
mo migrate build --project ./src/MyProject
mo migrate build --environment Production --verbose
mo migrate build --framework net10.0
```

### migrate run

Executes the generated migration against your MongoDB instance.

```bash
mo migrate run [OPTIONS]
```

**Options:**

| Option | Short | Description |
|--------|-------|-------------|
| (none) | | Uses global options only |

**Examples:**

```bash
mo migrate run
mo migrate run --project ./src/MyProject
mo migrate run --environment Production
```

## Generated Migration Files

When you run `mo migrate build`, the tool generates a `MigrationBuilder.cs` file in your project. This file contains:

### File Location

```
YourProject/
├── Migration/
│   └── MigrationBuilder.cs
```

### File Structure

The generated `MigrationBuilder.cs` includes:

1. **Initialization Method** - Automatically registers the migration with MongoObject
2. **RunMigration Method** - Executes all database operations
3. **Operations Data** - Serialized migration operations (create collections, add indexes, etc.)
4. **Client Configuration** - MongoDB client setup with encryption support if configured

### Example Generated File

```csharp
// Autogenerated, this will be overwritten the next time migrations are built.
using MongoDB.Driver;
using MongoDB.Driver.Encryption;
using MongoDB.Bson.Serialization;
using MongoObject.Core.Data;
using MongoObject.Core.Extensions;
using System.Runtime.CompilerServices;

namespace YourProject.Migration
{
    public partial class MigrationBuilder : IMigration
    {
        private IMongoClient _client;
        
        public MigrationBuilder()
        {
            var connection_string = MongoObjectsPluginRegistry.SchemaDocument["connection_string"].AsString;
            var clientSettings = MongoClientSettings.FromUrl(new MongoUrl(connection_string));
            _client = new MongoClient(clientSettings);
        }

        public async Task RunMigration()
        {
            var operations = BsonSerializer.Deserialize<Dictionary<string, List<MigrationOperation>>>(Operations);
            
            foreach(var operation in operations)
            {
                var dbinfo = MongoNamespace.Parse(operation.Key);
                var db = _client.GetDatabase(dbinfo.Database);
                foreach (var item in operation.Value)
                {
                    await MongoObjectsPluginRegistry.ExecuteAsync(item.GetType(), db, dbinfo.Collection, item);
                }
            }
        }

        [ModuleInitializer]
        public static void Initialize()
        {
            MongoObjectsPluginRegistry.RegisterMigration(async () =>
            {
                var builder = new MigrationBuilder();
                await builder.RunMigration();
            });
        }
    }
}
```

## Workflow Example

Here's a complete example of using the CLI tool to handle a schema change:

### 1. Define Your Document

```csharp
[MongoObject(CollectionName = "products", DatabaseName = "store")]
public partial class Product
{
    public partial string Name { get; set; }
    public partial decimal Price { get; set; }
    public partial string? Description { get; set; }  // New field
}
```

### 2. Build the Migration

```bash
mo migrate build --project ./src/Store.Api
```

Output:
```
Building Project...
Building and Testing Clients...
Checking for initial Changes...
✓ Migration file generated: Migration/MigrationBuilder.cs
```

### 3. Review Generated Migration

The tool creates `Migration/MigrationBuilder.cs` with operations to:
- Create the `products` collection (if new)
- Add the `Description` field to existing documents
- Apply any index changes

### 4. Run the Migration

```bash
mo migrate run --project ./src/Store.Api
```

Output:
```
Executing migration...
✓ Migration completed successfully
```

### 5. Commit Changes

Commit the generated `MigrationBuilder.cs` file to your repository:

```bash
git add src/Store.Api/Migration/MigrationBuilder.cs
git commit -m "Add migration for product description field"
```

## Configuration

The CLI tool reads configuration from your MongoObject setup. Ensure your project has:

### Connection String

Configure your MongoDB connection string in your application settings:

```csharp
services.AddMongoObject(options =>
{
    options.ConnectionString = "mongodb://localhost:27017";
    options.DefaultDatabase = "myapp";
});
```

### Environment-Specific Configuration

Use different configurations per environment:

```bash
mo migrate build --environment Production
```

The tool will use your `appsettings.Production.json` configuration.

## Common Scenarios

### Adding a New Collection

1. Create a new MongoObject document class
2. Run `mo migrate build`
3. Run `mo migrate run`

The tool automatically detects the new collection and generates creation operations.

### Modifying Existing Fields

1. Update your document properties
2. Run `mo migrate build`
3. Review the generated migration
4. Run `mo migrate run`

### Creating Indexes

Indexes defined in your MongoObject configuration are automatically included in migrations.

### Handling Encryption

If your project uses MongoDB encryption, the generated migration file includes encryption client setup and handles encrypted field operations.

## Troubleshooting

### "No Collections Found to process"

This message appears when:
- No MongoObject documents are defined in your project
- All documents are already synchronized with the database

**Solution:** Ensure your documents are decorated with `[MongoObject]` and the project builds successfully.

### "Please be sure to provide a connection String"

The tool cannot find a valid MongoDB connection string.

**Solution:** Verify your MongoObject configuration includes a valid `ConnectionString`.

### "The default database is undefined"

MongoObject is not properly configured.

**Solution:** Ensure `DefaultDatabase` is set in your MongoObject configuration:

```csharp
services.AddMongoObject(options =>
{
    options.DefaultDatabase = "myapp";
});
```

### Connection Timeout

The tool cannot connect to your MongoDB instance.

**Solution:**
- Verify MongoDB is running
- Check your connection string
- For local development, add `directConnection=true` to your connection string:
  ```
  mongodb://localhost:27017/?directConnection=true
  ```

### "Error creating schemas"

An error occurred while analyzing your document definitions.

**Solution:** Run with `--verbose` flag for detailed error information:

```bash
mo migrate build --verbose
```

## CI/CD Integration

### Non-Interactive Mode

For automated deployments, use the `--ci-deploy` flag:

```bash
mo migrate build --ci-deploy --environment Production
```

This mode:
- Validates the migration against the live database
- Does not prompt for user input
- Exits with appropriate status codes for CI/CD pipelines

### Example GitHub Actions Workflow

```yaml
name: Deploy Migrations

on:
  push:
    branches: [main]

jobs:
  migrate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      
      - name: Setup .NET
        uses: actions/setup-dotnet@v3
        with:
          dotnet-version: '10.0.x'
      
      - name: Install CLI Tool
        run: dotnet tool install --global Tenowg.MongoObjects.CliTool
      
      - name: Build Migration
        run: mo migrate build --ci-deploy --environment Production
        env:
          MONGODB_CONNECTION_STRING: ${{ secrets.MONGODB_CONNECTION_STRING }}
      
      - name: Run Migration
        run: mo migrate run --environment Production
        env:
          MONGODB_CONNECTION_STRING: ${{ secrets.MONGODB_CONNECTION_STRING }}
```

## Best Practices

1. **Always Review Generated Files** - Check the generated `MigrationBuilder.cs` before running migrations
2. **Test in Development First** - Run migrations in a development environment before production
3. **Commit Migration Files** - Include generated migration files in version control
4. **Use Environment-Specific Configs** - Keep different connection strings for different environments
5. **Enable Verbose Logging** - Use `--verbose` when troubleshooting issues
6. **Backup Before Production** - Always backup your MongoDB database before running migrations in production
