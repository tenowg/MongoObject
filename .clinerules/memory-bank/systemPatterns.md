## Key Technical Decisions

### 1. Document Wrapper Pattern
Documents are wrapped in `MongoDocument<T>`:
```csharp
public class MongoDocument<T> where T : class, IDocumentFile, new()
{
    public string Id { get; set; }
    public T? Document { get; set; }
    public BsonDocument Metadata { get; set; }
}
```
**Rationale**: Separates business data from metadata and MongoDB-specific concerns.

### 2. Change Tracking via Source Generation
The `TrackingObservableObject` base class provides:
- `INotifyPropertyChanged` implementation
- Change dictionary for tracking modifications
- Nested object tracking support
- Pipeline generation for MongoDB updates

**Generated Code Pattern**:
```csharp
public partial class MyDocument : TrackingObservableObject, IDocumentFile, ...
{
    public partial string Name 
    { 
        get => field; 
        set => SetField(ref field, value);
    }
}
```

### 3. Modular Source Generator with Equatable Models
The source generator uses a module-based architecture with **equatable models** for proper incremental caching:

**Module Interfaces**:
- `ICodeModule` - Single model processing (per document class)
- `ICodeModuleMultiple` - Batch processing (all document classes)

**Modules**:
| Module | Purpose | Output |
|--------|---------|--------|
| ValidatorModule | Compile-time validation | Diagnostics |
| MetadataModule | Generate metadata types | `{Name}Query`, `{Name}Record` |
| MongoObjectModule | Generate document partial class | Partial property implementations |
| DocumentSearchModule | Generate search classes | `{Name}Query` with ToMongoFilter |
| ObjectDiscoveryModule | DI registration | `RegisterDocuments{Namespace}()` |
| ExtensionModule | Per-class extensions | MetadataSearch, DocumentSearch, Add |
| ProjectionModule | Generate projections (WIP) | `{Name}{ProjectionName}` |

**Equatable Model Pattern**:
```csharp
// Models contain NO Roslyn symbols - only strings and primitives
internal sealed record PropertyModel
{
    public string Name { get; init; }
    public string FullName { get; init; }
    public bool IsMongoObject { get; init; }      // Pre-computed
    public bool IsTrackable { get; init; }        // Pre-computed
    public bool IsComplexUntrackedClass { get; init; }  // Pre-computed
}
```

**Why Equatable Models Matter**:
- Roslyn symbols (`INamedTypeSymbol`, `IPropertySymbol`) don't implement value equality
- Without equatable models, the incremental cache always misses
- This causes the generator to re-run on every keystroke
- With equatable models, the cache works correctly and only re-runs when relevant code changes

### 4. Dependency Injection Pattern
All services registered via `MongoObjectBuilder`:
```csharp
services.AddMongoObject(options => { ... })
        .RegisterDocument<MyDoc, MyDocQuery, MyDocRecord>()
        .AddWatchStream();
```

Or using the generated extension:
```csharp
services.AddMongoObject(options => { ... })
        .RegisterDocumentsMyNamespace();  // Generated by ObjectDiscoveryModule
```

### 5. Caching Strategy
Two-tier caching with:
- **Absolute Expiration**: Hard limit on cache duration
- **Sliding Expiration**: Extends on access

### 6. Nested MongoObject Query Pattern
For properties that are themselves MongoObject types, use BsonDocument as intermediate:
```csharp
// Generated in parent query's ToMongoFilter method
if (nestedProperty != null)
{
    var nestedFilter = nestedProperty.ToMongoFilter("Document.NestedProperty");
    var nestedSerializer = BsonSerializer.SerializerRegistry.GetSerializer<MongoDocument<NestedType>>();
    var renderArgs = new RenderArgs<MongoDocument<NestedType>>(nestedSerializer, BsonSerializer.SerializerRegistry);
    var bsonDoc = nestedFilter.Render(renderArgs);
    filters.Add(new BsonDocumentFilterDefinition<MongoDocument<ParentType>>(bsonDoc));
}
```
**Rationale**: `FilterDefinition<T>` cannot be directly converted between different `T` types, but BsonDocument can be re-wrapped.

## Component Relationships

### Document Lifecycle
```
1. Define → [MongoObject] attribute on partial class
2. Generate → Source generator creates partial implementation
3. Register → RegisterDocument<T>() in DI container (or use generated extension)
4. Use → IDocumentMonitor<T> for CRUD operations
5. Track → Automatic change tracking on property access
6. Save → SaveChanges() generates efficient update pipeline
```

### Source Generator Pipeline
```
SyntaxProvider → BuildCommonModel (equatable) → Cache Check → Execute Modules
                         │
                         ▼
              ┌─────────────────────┐
              │ ProcessAllProperties │
              │ - IsMongoObject      │
              │ - IsTrackable        │
              │ - IsComplexUntracked │
              └─────────────────────┘
```

### Update Pipeline Generation
```
Property Change → _changes dictionary → ProcessPossibleChanges()
                                              │
                                              ▼
                              TryGetPendingUpdatesPipeline()
                                              │
                                              ▼
                              ┌───────────────────────────────┐
                              │ $set: { "Document.Field": val }│
                              │ $unset: ["Document.NullField"] │
                              │ Metadata.LastModifiedAt: $$NOW │
                              │ Metadata.Version: $add [...]   │
                              └───────────────────────────────┘
```

## Critical Implementation Paths

### 1. Document Retrieval
```
Get(id) → Cache Check → MongoDB Query → Key Manager → Cache Store → Track Changes
```

### 2. Document Update
```
SaveChanges(doc) → Get Key → Check Locks → Build Pipeline → Transaction → Clear Changes
```

### 3. Change Tracking
```
Property Set → SetField() → OnPropertyChanged() → _changes Dictionary
                                                      │
Nested Object → TrackChanges(parent, tracking, name) ─┘
```

### 4. Cross-Assembly MongoObject Detection
```
Property Type → compilation.GetTypeByMetadataName() → GetAttributes() → IsMongoObject flag
```
**Note**: Works correctly for types from referenced assemblies because attribute lookup works across assembly boundaries.

## Design Patterns Used

1. **Repository Pattern**: `IDocumentMonitor<T>` abstracts data access
2. **Unit of Work**: `SaveChanges()` batches all changes
3. **Observer Pattern**: `INotifyPropertyChanged` for change notification
4. **Builder Pattern**: `MongoObjectBuilder` for fluent configuration
5. **Strategy Pattern**: Different watch modes (stream, polling)
6. **Decorator Pattern**: `MongoDocument<T>` wraps user documents
7. **Pipeline Pattern**: Source generator modules process models in sequence

## Performance Considerations

### Source Generator
- **Equatable models** enable proper incremental caching
- **StringBuilder** reduces string allocations during code generation
- **Pre-computed type checks** avoid repeated symbol lookups
- **CancellationToken checks** allow early termination on user input
- **Stateless generator** prevents stale data across compilations

### Runtime
- **Memory cache** with sliding/absolute expiration
- **Distributed locking** for concurrent access
- **Efficient update pipelines** (only changed fields)
- **Change tracking** at property level
